# 検証結果と制限

## 実施して通過した項目

- JavaScript構文検査、HTMLの相対参照、PWAのルート相対スコープ
- 同梱PDF.js 6.4.299による、独自に作成した2ページの人工PDFの読み込みとPNG描画
- ページ内の完全一致する文字列の取得、画像内の位置確認
- スペース番号、サークル名、複数販売物、価格の入力と表示
- URLのhttp/https制限、負の価格や不正範囲の拒否
- IndexedDBへの保存と読み直し、複数ページ切り替え
- 手動2点指定による範囲の保存
- 登録のみのバックアップ復元、異なるPDFとの照合失敗時の拒否
- PDFを含むバックアップの復元
- 端末内データの消去
- 不正PDFの読み込み失敗時に、現在のPDF・登録を保持
- 静的アプリ・Worker・フォント等を含むキャッシュ構築
- `/my-repository/` のようなリポジトリ配下でのオフライン取得
- 他のアプリのキャッシュや範囲を変更しないこと
- 配布物からイベントのPDF・画像・座標表、個人サイト情報、Git履歴を除外したこと

PDFの読み込みは実際のPDF.jsとCanvas実装、画面操作・保存はDOM/IndexedDBのテスト用実装、Service Workerはイベント/Cache APIのテスト実装で確認しました。実ブラウザのインストール試験や実機試験と同じものではありません。NodeのファイルURLから補助フォントを取得する際には警告が出ましたが、PDF描画と文字取得の検査は通過しています。ブラウザでは補助フォントを同梱のHTTP相対URLから取得します。

## 未検証・制約

- iPhone、Android実機での表示、指操作、ホーム画面インストール
- 実際のGitHub Pagesへの配信と公開URLでの読み直し
- あらゆるPDFのフォント・画像・暗号化・特殊形式の表示
- 大容量・多数ページでの低メモリ端末の動作
- PDFへのOCR、ブロックの自動判定、a/bの左右判定

PDFは30 MB・30ページまでです。端末の容量やPDFの複雑さによっては、それ以下でも処理できない場合があります。取り込み時に失敗した場合、既存データを置き換えません。

## 再実行できる基本テスト

Node.js 24以降:

    npm run build
    npm run check
    node tests/model.test.mjs
    node tests/offline.test.mjs

任意の詳しいテストには、開発用の `jsdom`、`fake-indexeddb`、`@napi-rs/canvas` と Pythonの `reportlab` が必要です。アプリの公開・利用には不要です。

    npm install --no-save jsdom fake-indexeddb @napi-rs/canvas
    python3 tests/make_fixture.py
    node tests/integration.test.mjs

生成される `tests/generated-fixture.pdf` は独自の人工テスト図です。配布ZIPには同梱していません。テスト後に削除してください。利用者自身のPDFやバックアップをリポジトリに追加しないでください。

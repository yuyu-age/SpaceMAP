# スペースリンクマップ

自分が用意したPDF配置図に、スペース番号・サークル名・本や販売物・価格・リンクを登録する、スマートフォン向けの静的Webアプリです。

この配布物にイベントのPDF・地図画像・座標表は入っていません。利用者が端末でPDFを選び、アプリがその端末内で表示と保存を行います。GitHub Pagesなどの静的配信で動きます。サーバーへのPDFアップロードや登録内容の同期機能はありません。

## 最初に確認すること

- アプリ本体のライセンスはまだ決めていません。公開前に `docs/LICENSE-選択について.md` を確認し、公開者自身で選択してください
- PDF.jsとフォント等の第三者ライセンスは `THIRD_PARTY_NOTICES.md` と `vendor/pdfjs/` に収録しています
- PDFを個人端末で読み込む方式でも、あらゆるPDFの利用が許されるという意味ではありません。各PDFの権利・利用規約を利用者自身が確認してください
- このZIPの作成時点では、GitHubへのアップロード・リポジトリ作成・GitHub Pages公開は行っていません

## 使い方

1. 「PDFを選ぶ」で利用できる配置図を選びます。30 MB・30ページまでです
2. 「＋登録」でスペース番号を入力します。サークル名、備考、複数の販売物名と価格（円）、リンク先、色を設定できます
3. 「PDFの文字から位置候補を探す」を押すか、「地図で範囲を指定」を選びます
4. 候補または選んだ枠を確認し、「この位置で保存」を押します
5. 色付きの枠を押すとリンクが開きます。リンク未入力の場合や同じ位置に登録が重なる場合は、登録一覧を開きます

地図はドラッグで移動、ピンチまたは＋・−で拡大縮小できます。ページは上部の選択欄で切り替えます。手動指定は、スペースのマス目全体の対角の2点を順にタップします。番号の末尾が `a`（例：あ20a）なら左半分、`b` なら右半分、`ab` または指定なしなら全体を塗ります。半マスの向きは登録フォームで変更できます。a・bでも半分だけを囲まず、マス目全体を選んでください。

拡大・移動後には保存してある元PDFから表示範囲を描き直し、小さな文字を確認しやすくします。端末負荷を抑えるため、表示範囲の描画は約400万画素・各辺4096ピクセルまでです。元のPDF自体が低解像度の画像の場合は、失われた文字の細部を復元できません。以前に取り込んだPDFも、元PDFが保存されていれば再取り込みは不要です。

### 自動配置の範囲

PDFの文字情報からスペース番号を検索します。近接する同じ行の文字が分割されている場合は組み合わせて照合し、a・b・ab付き番号は末尾を除いた番号も探します。同じ番号が複数見つかる場合は自動確定しません。表示画質を上げることと、PDFの文字情報から番号を探すことは別の処理です。

番号を囲む上下左右の閉じた枠線を確認できた場合は、そのマス目を候補にします。文字だけを小さなマーカーとして保存せず、枠線が見つからない場合は番号付近を表示して、マス目全体の手動指定を案内します。保存前に必ず位置・大きさ・塗り分けを確認してください。同じ番号のマス目が既に登録されていれば、a・b等の別登録でその範囲を再利用します。

画像だけのPDF、離れた文字と数字、回転した文字、途切れた・斜めの枠線などは手動指定を使ってください。OCRや島・ブロックの推測は行いません。PDFの種類が変わっても、特定のイベントの座標表を流用しません。

以前のバージョンで登録したマーカーは元の範囲を保ちます。半マス表示へ切り替えるには「編集」→「地図で範囲を指定」でマス目全体を指定し直してください。備考（2000文字まで）は編集・端末内保存・JSONバックアップに含まれます。

## 保存とバックアップ

- 元PDF、表示用ページ画像、文字位置、登録内容は、このサイトのIndexedDBに保存します
- 配信元へ送る処理はありません。広告・解析・外部APIも組み込んでいません
- 通常のアクセス時は、配信事業者にIPアドレス等の通信情報が伝わります。外部リンクを押すと、そのリンク先に接続します
- 端末・ブラウザ・URLの配信元が変わると保存領域も変わります。自動同期はありません
- ブラウザデータ消去・容量不足・アプリ削除などで保存内容を失うことがあります。大切な登録はJSONバックアップを保存してください
- 「バックアップ」は初期状態では登録情報だけです。「PDFを含める」を選ぶとPDF本体も含まれます。PDF入りファイルは個人保管用として扱い、再配布する前に権利を確認してください
- 登録だけのバックアップは、同じPDFを先に取り込んでから復元します。ファイルのハッシュを照合するため、ページ順や内容が変わった別のPDFには誤って当てはめません
- 「PDFと登録を消去」で、このアプリが現在保存しているデータを消せます。アプリ本体のオフラインキャッシュは残ります

## スマートフォンとオフライン

### iPhone

Safariで配信URLを開き、共有メニューから「ホーム画面に追加」します。表示される場合は「Webアプリとして開く」を有効にします。追加したアイコンからオンラインで一度開いてください。通常のSafari画面とホーム画面アプリで保存領域が分かれる場合があるため、登録はホーム画面アプリ内で始めてください。

### Android

Chromeで配信URLを開き、メニューの「インストールしてショートカットを作成」からインストールします。Chromeの版により表記が異なる場合があります。追加したアイコンからオンラインで一度開いてください。

### オフライン準備

「オフライン準備完了」が出るまで待ってから、PDFを取り込んで保存してください。初回はアプリ・PDF.js・補助フォント等を取得します。その後は保存したPDFと登録をオフラインで使う設計です。外部リンク先は通信が必要です。実際に使う端末で機内モードにして再起動し、表示・保存を確認してください。

iPhone/Android実機での操作・インストールは未検証です。最新版のSafariまたはChromeを推奨します。HTMLをファイルアプリで直接開く方式は対象外です。HTTPSまたは開発用localhostで配信してください。

公式説明:
- [Apple: Webサイトをアプリとして使う](https://support.apple.com/guide/iphone/iphea86e5236/ios)
- [Google Chrome: Androidのウェブアプリ](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=JA)

## GitHubとGitHub Pagesに公開する

このフォルダーがそのまま静的サイトの公開ルートです。PDFや個人のバックアップを追加しないでください。

### 簡単な方法: ブランチから配信

1. 公開するライセンス・説明・第三者表示を確認します
2. GitHubに自分のリポジトリを作り、ZIPの中身一式をルートへ置きます。`vendor/`、`src/`、`icons/`、`.nojekyll` も含めてください
3. リポジトリの Settings → Pages → Source で「Deploy from a branch」を選びます
4. 公開対象ブランチと `/(root)` を選び、保存します
5. GitHubが表示したURLを開き、PDF取り込み・登録・オフライン表示を確認します

公開サイトはインターネット上で閲覧されます。端末内のPDFや登録はリポジトリに入らず、公開対象にもなりません。

### 任意: GitHub Actions

`.github/workflows/pages.yml` は手動実行専用の設定です。Settings → Pages の Source を GitHub Actions にし、Actions画面から実行できます。GitHub内の標準トークンを使い、APIキー等は必要ありません。アップロード直後に自動で公開される設定にはしていません。

公式手順: [GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## ソースと更新

ブラウザが読むJavaScript・CSSがそのままソースです。ビルドやnpm installなしでも同梱済みの静的ファイルを配信できます。PDF.jsも同梱されておりCDNには依存しません。

- `index.html`: 画面
- `src/app.js`: 操作・表示・バックアップ
- `src/model.js`: 検証とIndexedDB保存
- `src/pdf-import.js`: 端末内PDF読み込み・描画
- `vendor/pdfjs/`: PDF.js本体・Worker・CMap・フォント・必要なWASMとライセンス
- `sw.js`: オフラインキャッシュ（自動生成）
- `scripts/build.mjs`: オフライン対象一覧・バージョンを生成
- `scripts/check.mjs`: 静的ファイルと公開時の基本チェック
- `tests/`: 基本テストと人工PDFの生成スクリプト

ソースや同梱ファイルを変更したら、Node.js 24以降で次を実行します。

    npm run build
    npm run check
    node tests/model.test.mjs

ローカル確認例（Python 3）:

    python3 -m http.server 8080

ブラウザで `http://localhost:8080/` を開きます。GitHub Pagesのリポジトリ配下URLでも動くよう、参照・Worker・キャッシュの範囲は相対パスです。URLの末尾のスラッシュを省かないでください。

検証内容と未検証項目は `docs/検証結果.md` に記載しています。

Android相当の画面サイズ・タッチ操作・高密度画面でChromiumの回帰確認を行う場合は、Pythonの `playwright` とChromiumも必要です。人工PDFを生成し、別ターミナルでHTTPサーバーを起動してから実行します。

    python3 tests/browser.test.py http://127.0.0.1:8080/

このテストは実際のPDF取り込み、部分描画、半マス・全マス、備考編集、バックアップ復元、オフライン再表示を確認します。Android実機の確認とは別です。
